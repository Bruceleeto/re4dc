## GAME_ROT_FSCA

Files: game/platform/pmc_fsca_sh4.S (the loop), game/platform/pmc_fsca.c (C twin, slow path, =2 check),
game/platform/include/re4dc_fsca.h (FSCA + residual), game30.mk (knob, rules, LINK_ORDER slot). Needs
GAME_PMC_KERNEL=1 and GAME_FP_CONTRACT=off (both in the recipe). It replaces pmc_sh4.S as re4dc_pmc_run, so every
part of cModel::partsMatCalc goes through one loop (no RotMatrix memo, no miss path):

- sin / cos per angle x: k = ftrc(x K), (s0, c0) = FSCA(k), d = (x - k S1) - k S2, s = c0 d + s0, c = c0 - d s0
  (K = 65536 / 2 pi; S1 + S2 = 2 pi / 65536 with S1 short enough that k S1 is exact). |x| < 2^-27 gives fdlibm's
  exact (x, 1) (FSCA(0) is (+0, 1), so only -0 and denormals need a fixup); |x| > 2 pi or NaN sends the whole part
  to the C twin with re4dc_sincosf.
- then RotMatrix's products in its order, ScaleMatrix's, pos as integer words, the copy to mat: the same IEEE single
  operations as the C twin, so the assembly is bit-identical to it (=2 checks every part).
- scheduling: lane fm's list scheduler (tools/game30/pmc_fsca/lsched.py) under the hw model's pairing rules and
  latencies; 162 instructions, 88 issue cycles per part without memory stalls (minisim.py). The next part's lines are
  fetched with PREF (pList, ang / scale, pos, both ends of mat + l_mat). The loop is bus-bound after that: the two
  whole 32-byte lines inside mat + l_mat (from (part + 0x0C + 31) & -32; the 96 bytes always hold two) are
  allocated with MOVCA.L instead of filled from memory (all 24 words are stored afterwards, nothing reads them in
  between): -0.15 ms per tick.
- LINK_ORDER: the order file lists pmc_sh4.o. Left out of the order, the new kernel lands in the unordered tail and
  the ordered hot code after the slot moves 228 bytes down; the knob therefore links with a copy of LINK_ORDER in
  OBJDIR with that line renamed to pmc_fsca_sh4.o (the hot code after it moves 256 bytes up instead). That took the
  other-function drift on the fight from +0.49 / +0.51 to -0.01 / +0.25 ms. Regenerate the order
  (tools/d367/ordgen_c3.py) when landing.
- .text grows 864 bytes. r22's .text ends 112 bytes below an 8 KiB step, so .rodata / .data / .bss and the heap
  move up 8 KiB (any lane adding more than 112 bytes of code does this): same scene (ENC census lines equal except
  the ENC_GS model address, 0x8ca47f00 -> 0x8ca49f00).

Knob off: image and overlay byte-identical to int-cF (fm-cA5) and int-tfF (fm-tfA5) with SOURCE_DATE_EPOCH pinned;
missing.txt empty in every arm.
