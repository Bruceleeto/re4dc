## The t11 fx trace pairs: why their STRICT failed (offline analysis of the existing logs)

fx7tr-h2-0 / -2 (FX_LEVEL 0 / 2 + PS2_FX_GEN + EFFECT_OWNERS_ALL) against fxtr-h2-k: STRICT FAIL and decisions
MUST-DIFFER on the `af` field only, from tick 1672 (the r100 s30 movie start). Every other must-match field is equal
up to tick 4700, and s30 plays 340/340 frames in both runs. The fx arm has one more failed 0x3600 "native UI texture
staging" allocation, and the movie heap evicts one more motion key. Heap 4 at s30 is exactly 8192 B smaller.

Cause: the image size, not the knobs. The run fxtr-h2-k used a kT build padded to the earlier tT `_end` (8c410b9c).
The fx arms end at 8c412d5c, which is 0x21c0 larger. kT was later re-padded to 8c412d5c, but its run (fx7tr-h2-k)
captured nothing, and the level-1 run hit the harness capacity guard. So no valid pair exists yet. The fx12 trace arms
are all padded to one `_end` (fx12-build.sh). The same coupling means a release that adds the generator table gives
up about 8 KB of heap 4 at s30. s30 still plays here.
