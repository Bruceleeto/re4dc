## The t11 fx trace pairs: why their STRICT failed (offline analysis of the existing logs)

fx7tr-h2-0 / -2 (FX_LEVEL 0 / 2 + PS2_FX_GEN + EFFECT_OWNERS_ALL) against fxtr-h2-k: STRICT FAIL and decisions
MUST-DIFFER on the `af` field only, from tick 1672 (the r100 s30 movie start). Every other must-match field is equal
up to tick 4700, and s30 plays 340/340 frames in both runs. The fx arm has one more failed 0x3600 "native UI texture
staging" allocation, and the movie heap evicts one more motion key. Heap 4 at s30 is exactly 8192 B smaller.

Cause: the image size, not the knobs. The run fxtr-h2-k used a kT build padded to the earlier tT `_end` (8c410b9c).
The fx arms end at 8c412d5c, which is 0x21c0 larger. kT was later re-padded to 8c412d5c, but its run (fx7tr-h2-k)
captured nothing, and the level-1 run hit the harness capacity guard. So no valid pair exists yet. The fx12 trace arms
are all padded to one `_end` (fx12-build.sh). The same coupling means a release that adds the generator table gives
up about 8 KB of heap 4 at s30. s30 still plays here.

## 10-14 night: PS2-sourced effect pictures (FX_PS2_PACK), PAL4, pool, fragmentation

- The churners: TEX_CHECK and the load log tie the reloaded fmt 8 sets to etc/core.das EFF#1 ids 0x26 (64x48 x30),
  0x28 (64x96 x30) and 0x2e (96x96 x30), and to r101.arc#7 0xe3 smoke / 0x29 fire. In the test 11 control, 1711 of
  2357 loads were these sets. PS2 Core.dat EFF#1 has the same 56 ids, and PS2 r101.dat#7 matches the GameCube #7 by id.
- fx_ps2_pack.py (aa18161c, library mode d2ebf9d0 / 5182665f) puts the PS2 picture of each frame under the GameCube
  key. Pixels are PSMT4. A TEX0 flag 1 picture is stored transposed and is turned back. Each id shares one palette, a
  16-colour k-means over its frames (mean premultiplied error 0.2..1.7 of 255). The package is PAL4 ARGB4444, and its
  header flags hold the covered texels. Runtime FX_PS2_PACK=1 scales effect UVs by those texels (native_ui.cpp
  RE4DC_COVER_W/H), and FX_SPRITE_TRIM skips such packages. Knob off: image identical (fx12k6tP, fx12k7tP).
- Coverage, r101 + core:
  - 0xf4 has 4 GameCube frames and 1 PS2 frame: all 4 keys get the PS2 picture. Frame count, timing and Rnd stay the
    GameCube data.
  - GameCube-only 0x33 / 0xcb / 0xf6 (the mist sheets PS2 cut) keep their GameCube packages. The FX level controls them.
  - PS2-only 0x0c has no GameCube reference and is not packed.
  - 31 core ids are swizzled PSMT4 or 8 bpp on the PS2 (128x128 / 256x256 singles). They are not converted yet and
    keep their GameCube packages.
- PS2 library: ps2lib/effects-tex/<common|room>/ plus INDEX.tsv rows (class effects-tex, 236 rows, 76 NONE) and
  NOTES.tsv. The 17 route rooms were converted in one pass (20 s), 488 packages, 2.5 MB. A tex.pak is built with
  `fx_ps2_pack.py pack <in> <out> <ps2lib>`: tex-t11-ps2lib.pak, sha256 653e622b...
  The 17-room gate moved to test 14 (complete world).

- Fragmentation of 9fe00ef7: a 256x256 RGB5A3 PS2 world texture (its key is in the r111-ps2 world packages). r101 draws
  it, but it is not in r101's preload table, so it is LRU-loaded into a fragmented pool. UI_FRAG_WINDOW=2 (vr lane)
  halves the failures. Neither slab variant helps. The fix that removes the failure is to preload it with the r101 PS2
  world, so it is allocated large-first at room entry. That is the world build, which Codex owns.
