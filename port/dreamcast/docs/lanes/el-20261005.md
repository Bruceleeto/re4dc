## Step 2: GAME_LQ_MEMO

First version (v1, measured, dropped): the wallAdjust repeat plus a 128-entry memo of the route line tests
(rckLineHitCheck -> SatMgr.hitCheck(a, b, NULL, NULL, attr, mask), keyed by the ends, attr, mask, seCk and an epoch
of the room's live pieces: identity, tables, block root, matrices; .bss +7,680 B, .text +1,376 B, crossing the
8 KiB step). =2: 0 mismatches (fight 52,224 lookups, 38 % hits; prejump 35.5 %, quiet 34.7 %, square 22 %). Its
gates were clean (H2 / fight MUST-IDENTICAL with `om` / `ef` in the 741..1217 sub-screen window only, bell
STRICT, look = control). But the route tests' memo bought nothing: the hits are the cheap queries and the world
check (every SatMgr slot's isAlive per lookup) costs what a cheap walk costs. Category deltas fight / prejump /
square: route / sight lines -0.016 / -0.016 / -0.042 drawn, the memo's own code +0.062 / +0.105 / +0.120 drawn
(skipped likewise); square function level +0.056 / +0.008 (a loss). Kept as a patch in the lane evidence
(el-20261005/lqm-v1-route.patch), not in the branch.

Second version (v2): the wallAdjust repeat alone, comparing both ends; .text +160 B, crossing the step; the
placement drift (MotionMoveCore +0.11 from I-cache conflicts) hid most of the gain in whole-tick totals.

Final (v3, committed): the wallAdjust repeat, comparing pos only (oldPos is the callers' local, written by
nothing in wallAdjust: hitCheck2 moves only pos1 and only on a hit, the sphere pass gets the copy p0). The
second query then writes SEck (the same value) as the walk would; `hit` is a dead local. Trace builds record the
first walk's decision notes (re4dc_dt_note -> re4dc_lqm_note) and give them again, so the LX hashes and counts
are those of two walks. =2 walks every time and counts "LQM pair= pairsame= pairmis=".
